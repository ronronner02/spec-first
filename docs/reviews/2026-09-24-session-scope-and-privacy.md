# 会话结束边界与输出隐私审阅

## 结论

已确认并修复“只读审阅被旧 PRD 校验拉入需求编写”的共享根因，清理默认输出署名，并修复本轮审阅发现的依赖、文件写入、清理预检、跨平台路径和测试隔离问题。修订包已安装，本次涉及的生成文件已定向同步到已有工作区。

**这不是全仓无缺陷或全量验收通过的声明。** 聚焦回归通过；完整 Windows 单测仍有 148 项失败，失败用例名称均已存在于原始基线。真实任务验证只覆盖下述 Claude 场景，未证明所有宿主、所有长任务或中转渠道问题都已解决。

- 修复分支：`fix/session-scope-and-output-privacy`。
- 交付范围为修复分支，不包含合并默认分支、创建上游 PR 或发布新版本。
- 没有访问或变更业务服务器、渠道、数据库或其他业务服务。

## 审阅范围与证据等级

采用风险导向的全仓审阅：先检查目录、入口、依赖和基线，再跟踪安装/清理、原子写入、宿主投射、PRD hook、输出模板及测试入口的实际调用路径。审阅覆盖源码、测试、打包文件和本地生成资产，不代表对全仓数千个文件逐行审完。

| 范围 | 实际覆盖 | 限制 |
| --- | --- | --- |
| CLI 文件操作 | 原子替换、操作计划、路径及链接边界、回归测试 | 路径预检不是完整事务，也不是并发锁 |
| PRD 生命周期 | Claude/Qoder 结束检查、原有写入凭据保护、当前回合归属 | Qoder 原生 hook 激活仍为未验证状态 |
| 多宿主生成 | 支持宿主的投射源码、完整单测、六宿主打包初始化烟测 | 生成成功不等于每个宿主实机加载成功 |
| 输出隐私 | PR、HTML、解释文档、审阅报告、交付检查表和语言策略 | 保留许可证、必要版权和机器校验字段 |
| 依赖 | 锁文件、依赖审计、离线 YAML 副本及预算复现 | 审计零命中不是整个项目无漏洞证明 |
| 实际任务 | 新会话保留真实 hook，并调用 Read/Edit/Skill | 限定样本；完整开放式审阅有一次超时 |

本轮是串行源码审阅和自审，没有独立审阅者。对代码复用、质量和效率进行了逐项复核；没有为了减少行数再引入无关重构。

## 确认的问题与修复

### 1. 结束检查把共享工作区变更误认成本次任务

旧实现通过 Git dirty/untracked 状态寻找 PRD。只读审阅也会拾取以前遗留或其他 CLI 修改的文件；这些文件的旧 readiness 凭据触发拦截，反馈又要求返回需求流程。Claude 缺少结束 hook 的防重入，模型可能继续执行，而不是等待用户回答。

修复落在 `templates/claude/hooks/prd-readiness-guard`、`templates/qoder/hooks/prd-readiness-guard`，共用 `skills/spec-prd/scripts/lib/hook-session-scope.cjs`：

- 读取宿主的 `session_id` 和 `transcript_path`，最多读取末尾 8 MiB。
- 沿 `uuid` / `parentUuid` 选取当前真实用户回合及当前消息分支，排除 sidechain 与元消息授权。
- 仅接受成功的 `Write` / `Edit` / `MultiEdit` 回执；Edit 类工具结合 `originalFile` 或当前回合的已知内容重建结果。
- 核对磁盘内容，避免接管已被其他会话改写的文件。仅归一 CRLF/LF，不忽略其他内容差异。
- 不再使用全工作区 Git 状态作为任务归属；`stop_hook_active` 时直接结束。
- 校验提示明确不是新的授权。未获需求编写授权时，报告遗留缺口并等待选择，不自动切换流程。
- 当前回合真正写入的 ready/final PRD 仍经过原有 finalize 校验；原有写入前机器字段保护保留。

缺少完整记录、Shell 写入、压缩前历史、超出读取窗口或未知宿主格式时，不提供自动硬保证，仍需显式 finalize。Stop 放行不表示 PRD readiness 通过。内容一致性检查也不等于文件锁。

### 2. 默认模板自动加入署名和宣传页脚

移除了 PR 的默认宣传页脚、HTML 的 composing-skill footer、解释文档署名以及报告模板中的生成来源字样。交付检查表不再要求工具归属。项目级和用户级语言策略明确禁止未经当前用户具体要求的自动署名。

原安装中的隐私定制先逐项比较后合入源码，没有用整份旧 README 回退当前仓库信息。额外清理了 ideation 文档中遗漏的 composition-footer 例外。许可证、离线依赖版权、正常功能说明及 readiness 机器凭据未删除。

### 3. YAML 空映射合并绕过预算

依赖审计确认 `js-yaml` 3.15.1 受 GHSA-2883-xcg3-v3hh 影响：空映射合并未正确消耗 `maxTotalMergeKeys` 预算。

锁文件覆盖版本、配置读取器及离线副本同步更新至 3.15.2。回归样本只使用三个空 alias 和预算 1；新版本按预期拒绝。测试同时确认离线副本与安装包分发文件逐字节一致。

### 4. 原子替换丢失原文件的 POSIX 权限

`src/cli/atomic-write.js` 原先重建临时文件后替换 inode，可能把原配置的 `0600` 变成默认权限。现在读取原 mode、排他创建临时文件，并在替换前保留 mode。

Windows 回归确认了原权限传递和写入结果；不把这项修复描述为完整的 Windows ACL 保留能力。

### 5. 清理计划发现越界前已经执行部分删除

`src/cli/state.js` 原先边检查边执行；若第二个操作越界，第一个合法文件可能已经删除。现在先检查整个计划的目标，再执行；原来的逐项检查仍保留。

遍历逃逸和 junction 逃逸用例均确认：错误计划在任何删除发生前被发现，项目文件和外部文件保持原样。不扩大声称为完整事务或并发原子性。

### 6. Windows 上解析 POSIX npm 路径错误

`scripts/lib/npm-cli.cjs` 选择路径 API 时，非 Windows 路径误用了宿主 `path`。改为显式 `path.posix`。原始基线的两个失败用例已通过。

### 7. 上游测试污染真实用户配置

首轮基线测试确实误写了用户级开发者身份和两份入口指令。这是本次验证的实际副作用，已经向用户说明，未将其当作既有状态隐去。

根因有两层：Windows 的 `os.homedir()` 使用 `USERPROFILE`，旧测试只改变 `HOME`；Jest VM 内修改 `process.env` 又不等于修改原生进程环境。

新增 `tests/global-setup.cjs` 与 `tests/global-teardown.cjs`，在创建 Jest VM 前隔离 HOME、USERPROFILE 及相关宿主配置目录，结束后清理本次临时目录。新增测试检查原生 home 和子进程环境的一致性。

恢复时保留用户原有网络配置，受影响规则依据既有同源策略和运行前会话证据恢复。开发者初始化元数据来自最近已验证的历史快照，**不是本轮开始前逐字节备份**。后续多次哈希核对、隔离测试和本地同步未再次改写受影响文件。个人配置内容、恢复明细及核对记录仅保留在本地交付材料中。

测试产生的两份历史验证 JSON 差异已单独保存后恢复，没有刷新或补造历史审阅凭据。

### 真实任务观察

所有任务运行在隔离样本目录，使用真实 Claude CLI 与真实 hooks；未恢复或修改用户原有会话。

1. 开放式“阅读项目并审阅可行性”任务在 240 秒超时；过程中进入只读审阅，没有观察到需求编写，但未完成，故不计验收通过。

## 遗留边界

- 全量 Windows 单测和集成测试仍有失败；逐项清零是后续明确范围的工作，当前不声称已解决。
- 跨 CLI 接续工作仍然可行，文件没有绑定到原会话；接续者成功改写 PRD 后，该文件进入其当前回合检查范围。若接续者只接收已有 PRD、没有再次修改就直接收尾，Stop 不自动继承上一会话的校验范围，仍需显式 finalize。“用户明确接续后继承关联 PRD 校验范围”尚未实现，本次修复未引入任务锁，也未恢复全工作区扫描。
- Qoder 激活、其他宿主真实任务、长 transcript/压缩和 Shell 写入的自动归属没有现场全覆盖。
- 单模型自审不是独立审阅，建议正式发布前补独立检查。
- 当前结论为：**已验证的局部修复与本地同步，整体验收降级**。不得据此宣称整仓无漏洞、全部宿主一致、完整长任务稳定或服务器渠道修复完成。
